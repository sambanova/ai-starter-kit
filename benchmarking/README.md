# Overview

This AI Starter Kit evaluates the performance of different LLM models hosted by [SambaNova.ai](https://sambanova.ai/), letting you configure LLMs with different parameters and measure performance metrics. The Kit includes:
- Configurable SambaNova Cloud connectors (also works with any OpenAI-compatible endpoint from another provider).
- An app with four modes: Synthetic, Real Workload, and Custom performance evaluation, plus a Chat interface. The three evaluation modes let you select one or more of **Kit, vLLM, and aiperf** and compare results side by side.
- A set of bash scripts that are the core of the performance evaluations and provide more flexibility to users.

This sample is ready-to-use. We provide setup instructions, instructions for running as-is, and instructions for customizing.

# Before you begin

You must be a SambaNova customer with a SambaNova Cloud API key, and have your environment set up first. See the [FAQ](./FAQ.md) for common questions.

_These steps assume a Mac/Linux/Unix shell. On Windows, adjust commands for navigating folders, activating virtual environments, etc._

## Clone this repository

```bash
git clone https://github.com/sambanova/ai-starter-kit.git
```

## Set up the inference endpoint, and environment variables

Self-service provision an API endpoint using SambaNova Cloud, then follow the instructions [here](../README.md#getting-a-sambanova-api-key-and-setting-your-generative-models) to set your environment variables.

**Notes**:
1. Modify `SAMBANOVA_API_BASE` if you'd like to use a different SambaNova URL.
2. You can also point at any OpenAI-compatible endpoint from another provider — generate an API key there and map it to the same environment variables.

## Create the (virtual) environment
1. (Recommended) Create and activate a virtual environment (Python 3.11 recommended):
    ```bash
    python<version> -m venv <virtual-environment-name>
    source <virtual-environment-name>/bin/activate
    ```

2. Install dependencies:
    ```bash
    cd benchmarking # If not already in the benchmarking folder
    pip install uv
    uv pip install -r requirements.txt
    ```

_Note: vLLM and aiperf are also installed (via `requirements.txt`) for the optional vLLM/aiperf comparisons. Both drive a remote endpoint using your existing SambaNova credentials — no local GPU or extra setup needed._

# Use the starter kit

- [*GUI Option*](#gui-option): plots and configuration from a web browser.
- [*CLI Option*](#cli-option): run from the command line, with more flexibility.

## GUI Option

The GUI uses Streamlit. Useful for analyzing outputs graphically, since results are shown as plots. See the [FAQ](./FAQ.md) for issues.

### Deploy the starter kit GUI

From the `benchmarking` folder:

```shell
ulimit -n 4096
streamlit run streamlit/app.py --browser.gatherUsageStats false 
```

### Full Walkthrough

There are 4 options in the left sidebar. Pick the one that suits your needs.

<details id="synthetic-performance-evaluation">
<summary><strong>Synthetic Performance Evaluation</strong></summary>

Evaluates the selected LLM on synthetic data generated by this tool.

![Synthetic Performance Evaluation](./imgs/synthetic_performance_eval.png)

1. **Select benchmark tool(s) to run** from the multiselect: **Kit** (default, the Starter Kit's own evaluator), **vLLM** (`vllm bench serve`), **aiperf** (`aiperf profile`) — all against the same endpoint, no local GPU needed. Selecting one tool shows its full results; selecting more runs them all (each with its own live status panel) and, once all finish, shows a side-by-side comparison instead of individual plots.

2. **Enter a model name and choose the API type.** Use one of the models on the website with `SambaNova Cloud` selected, e.g. `Meta-Llama-3.3-70B-Instruct`. _Specific prompting support exists for GPT, Llama, Gemma, Mistral, Deepseek, Qwen, Solar, and Eeve — other models can work, but token counts may drift from what's specified._

3. **Multimodal image size** (if the model is multimodal): Small (500x500px), Medium (1000x1000px), or Large (2000x2000px); otherwise N/A. **Warning!** Multimodal models may trigger guardrails — adjusting input/output tokens can help.

4. **Configuration parameters:**
   - **Number of input/output tokens** (*default*: 1000/1000).
   - **Number of total requests** (*default*: 10) — the run can time out before finishing; adjust **Timeout** accordingly.
   - **Number of concurrent requests** (*default*: 1) — set above the largest batch size you want to test (typical sizes: 1, 4, 8, 16).
   - **Number of warm-up requests** (*default*: 0/disabled): throwaway requests before the measured run, discarded so cold-start/batch ramp-up don't skew results. Supported by all three tools (vLLM: `--num-warmups`, aiperf: `--warmup-request-count`). Shares the **Timeout** budget with the measured run.
   - **Timeout** (*default*: 600s), shared across warm-up + measured phases.

5. **Run it.** Click `Run!` — each selected tool gets its own status panel (progress bar, plus a live log for vLLM/aiperf), collapsing to a checkmark when done or staying open with an error icon if it failed. `Stop` only aborts an in-progress run (disabled otherwise — it never blocks starting a new one). **Warning:** stopping a run with many concurrent/high-token requests may leave some still running on the API; wait 1–2 minutes before retrying. `Download Results` is always visible, enabled once the run finishes, and zips every tool's output files into one subfolder each.

6. **Analyze results.** _Not all endpoints support server-side stats — you may see client+server or client-only metrics._ Six plots, split by batch size where applicable: TTFT distribution, end-to-end latency distribution, output throughput distribution, mean ITL distribution, total output throughput per batch size, and a request timeline (Gantt). Selecting only vLLM or aiperf shows the same plots, client-side only. Selecting 2+ tools replaces all six with a **Summary Metrics Comparison** table (duration, requests, tokens, throughput, TTFT/ITL — one column per tool) and a **TTFT Distribution Comparison** chart.

7. **Customize synthetic prompts** — found [here](./prompts/); add/edit/remove following the existing structure.

8. **Common examples:**
    1. Dynamic batching speed — 250/250 in/out tokens, 80 requests, concurrency 20, timeout 600.

        ![dynamic_batching_speed-ttft](./imgs/dynamic_batching_speed-ttft.png)
        ![dynamic_batching_speed-latency](./imgs/dynamic_batching_speed-latency.png)
        ![dynamic_batching_speed-output_throughput](./imgs/dynamic_batching_speed-output_throughput.png)
        ![dynamic_batching_speed-gantt](./imgs/dynamic_batching_speed-gantt.png)

    2. High input and output tokens — 2000/2000 in/out tokens, 80 requests, concurrency 25, timeout 600.

        ![high_input_output_tokens-ttft](./imgs/high_input_output_tokens-ttft.png)
        ![high_input_output_tokens-latency](./imgs/high_input_output_tokens-latency.png)

        ![high_input_output_tokens-gantt](./imgs/high_input_output_tokens-gantt.png)

    3. Running multiple concurrent requests — 250/250 in/out tokens, 400 requests, concurrency 80, timeout 600.

        ![running_multiple_concurrent_requests-ttft](./imgs/running_multiple_concurrent_requests-ttft.png)
        ![running_multiple_concurrent_requests-latency](./imgs/running_multiple_concurrent_requests-latency.png)

</details>

<details id="real-workload-performance-evaluation">
<summary><strong>Real Workload Performance Evaluation</strong></summary>

Evaluates the selected LLM under requests paced open-loop over time (by QPS), instead of a closed-loop concurrent burst.

![Real Workload Performance Evaluation](./imgs/real_workload_performance_eval.png) 

1. **Select benchmark tool(s) to run** — same multiselect and behavior as [Synthetic, step 1](#synthetic-performance-evaluation).

2. **Enter a model name and choose the API type** — same as [Synthetic, step 2](#synthetic-performance-evaluation).

3. **Multimodal image size** (if applicable) — same as [Synthetic, step 3](#synthetic-performance-evaluation). Kit-only; disabled when a non-Kit tool is selected.

4. **Configuration parameters:**
   - **Number of input/output tokens** (*default*: 1000/1000), **Number of total requests** (*default*: 10) — same as Synthetic.
   - **Queries per second** (*default*: 1.0): requests/sec sent to the endpoint; values <10 recommended to avoid rate limits.
   - **Queries per second distribution** (*default*: constant): `constant` or `exponential` wait time between requests. `constant` maps exactly for aiperf, only approximately for vLLM (no exact constant-rate mode — see [`vllm/README.md`](./benchmarking_tools/vllm/README.md)); `exponential` maps exactly for both.
   - **Max concurrent requests (vLLM/aiperf only)** (*default*: 100): a concurrency ceiling those CLIs require even in QPS-paced mode (Kit's real-workload mode has none). Disabled unless a non-Kit tool is selected.
   - **Number of warm-up requests** (fired together, not QPS-paced) and **Timeout** — same semantics as Synthetic.

5. **Run it** — same Run!/Stop/Download behavior as [Synthetic, step 5](#synthetic-performance-evaluation).

6. **Analyze results** — same as Synthetic minus the Mean ITL plot (five plots instead of six).

7. **Customize synthetic prompts** — same as [Synthetic, step 7](#synthetic-performance-evaluation).

</details>

<details id="custom-performance-evaluation">
<summary><strong>Custom Performance Evaluation</strong></summary>

Evaluates the selected LLM on your own dataset.

![Custom Performance Evaluation](./imgs/custom_performance_eval.png) 

1. **Prep your dataset**: `.jsonl`, one JSON object per line, each with a `prompt` key (add `image_path` for multimodal). Example: [`custom_prompt_example.jsonl`](./prompts/custom_prompt_example.jsonl). **Warning!** Multimodal guardrails may trigger — changing the prompt can help.

2. **Upload the jsonl file** via the sidebar.

3. **Select benchmark tool(s) to run** — same multiselect as [Synthetic, step 1](#synthetic-performance-evaluation). vLLM accepts the uploaded dataset as-is; aiperf converts it internally — no extra steps either way.

4. **Enter a model name and choose the API type** — same as [Synthetic, step 2](#synthetic-performance-evaluation).

5. **Configuration parameters:**
   - **Number of output tokens** (*default*: 256): caps generated tokens per request — same field as Synthetic/Real Workload, just optional here since the dataset sets input length.
   - **Num Concurrent Requests** (*default*: 1), **Num Warm-up Requests**, **Timeout** (Kit-only) — same as Synthetic.

6. **Run it** — same Run!/Stop/Download behavior as [Synthetic, step 5](#synthetic-performance-evaluation).

7. **Analyze results** — same five plots as Real Workload.

</details>

<details id="performance-on-chat">
<summary><strong>Performance on Chat</strong></summary>

Measures performance during a multi-turn conversation.

![perf_on_chat_image](./imgs/performance_on_chat.png)

1. Enter a model name and choose `SambaNova Cloud` as the API type, e.g. `Meta-Llama-3.3-70B-Instruct`.
2. If multimodal, upload an image via the sidebar (limit 200MB). **Warning!** Guardrails may trigger — changing the prompt can help.
3. Set **Max tokens to generate** (*default*: 256).
4. Press `Run!` to start the chat session.
5. Ask anything — each response has an expander showing **Latency (s)**, **Throughput (tokens/s)**, and **Time to first token (s)**.

![perf_on_chat_image](./imgs/performance_on_chat_results.png)
</details>

## CLI Option

Run from a terminal — useful for values beyond the GUI's limits, or scripting. See the [FAQ](./FAQ.md) for issues.

Run `ulimit -n 4096` once per terminal session before invoking the evaluator, to raise the open-file-descriptor limit for higher-concurrency runs.

**This CLI runs the Kit's own native evaluator** (`benchmarking_tools/kit/src/evaluator.py`). For vLLM or aiperf (including aiperf's AgentX MVP agentic-coding benchmark), see [`vllm/README.md`](./benchmarking_tools/vllm/README.md) and [`aiperf/README.md`](./benchmarking_tools/aiperf/README.md).

**`--mode` is optional**, inferred from whichever other arguments you give:

1. `--input-file-path` given → **custom**.
2. `--num-concurrent-requests` equals `--num-requests` (or either omitted) → **synthetic**.
3. `--num-concurrent-requests` and `--num-requests` both given and differ → **real_workload**.

Pass `--mode` explicitly to bypass inference. Unrecognized arguments for the picked mode are ignored (with a terminal note) rather than erroring, so a caller can pass every mode's flags unconditionally.

`--qps-distribution` accepts `constant` or `exponential`.

There's a separate editable-variables quickstart script per mode, each passing `--mode` explicitly and exposing only that mode's own parameters:
- [`benchmarking_tools/kit/quickstart_synthetic.sh`](./benchmarking_tools/kit/quickstart_synthetic.sh)
- [`benchmarking_tools/kit/quickstart_real_workload.sh`](./benchmarking_tools/kit/quickstart_real_workload.sh)
- [`benchmarking_tools/kit/quickstart_custom.sh`](./benchmarking_tools/kit/quickstart_custom.sh)

Edit the variables at the top of whichever matches your use case, then `cd benchmarking_tools/kit && sh quickstart_<mode>.sh`. The examples below show the equivalent direct `python benchmarking_tools/kit/src/evaluator.py <flags>` call — same evaluator either way.

<details id="synthetic-dataset">
<summary><strong>Synthetic Dataset</summary></strong>

1. Set `--num-concurrent-requests` equal to `--num-requests` (or pass `--mode synthetic`). Relevant flags:
  - **`--model-names`**: model name(s) — see [Synthetic, step 2](#synthetic-performance-evaluation).
  - **`--llm-api`**: API type.
  - **`--results-dir`**: output dir. _Default_: `./data/results`.
  - **`--num-concurrent-requests`** (_default_: 16), **`--num-requests`** (_default_: 16, may time out first — see `--timeout`).
  - **`--num-warmup-requests`** (_default_: 0): throwaway requests before the measured run, sharing the **timeout** budget.
  - **`--timeout`** (_default_: 600): shared across warm-up + measured phases.
  - **`--num-input-tokens`** (_default_: 1000) / **`--num-output-tokens`** (_default_: 150): recommended ≤2000 either way.
  - **`--multimodal-image-size`**: `na`/`small`/`medium`/`large` (_default_: `na`). Same guardrail warning as the GUI.
  - **`--use-multiple-prompts`** (_default_: False): random prompt selection instead of one fixed prompt (text-instruct models only — [customize here](./prompts/user-prompt_template-text_instruct.yaml)).
  - **`--save-llm-responses`** (_default_: False): saves response texts to a `response_texts`-suffixed file.
  - **`--use-debugging-mode`** (_default_: False): more detail per request, higher latency.

   To run vLLM instead of (or alongside) Kit, see [`vllm/README.md`](./benchmarking_tools/vllm/README.md).

2. Run it — edit [`quickstart_synthetic.sh`](./benchmarking_tools/kit/quickstart_synthetic.sh) and `sh quickstart_synthetic.sh`, or call directly:
```shell
python benchmarking_tools/kit/src/evaluator.py \
  --mode synthetic \
  --model-names Meta-Llama-3.3-70B-Instruct \
  --results-dir ./data/results \
  --llm-api sncloud \
  --num-concurrent-requests 16 \
  --num-requests 16 \
  --num-input-tokens 1000 \
  --num-output-tokens 1000 \
  --multimodal-image-size na \
  --use-multiple-prompts False
```

3. **Analyze results** — saved to `--results-dir` as `synthetic_<MODEL_IDX>_<MODEL_NAME><MULTIMODAL_SUFFIX>_{NUM_INPUT_TOKENS}_{NUM_OUTPUT_TOKENS}_{NUM_CONCURRENT_REQUESTS}_{MODE}`, two files per run:
   - `_individual_responses`: per-request tokens, TTFT, E2E latency, throughput (client + server where available). See `notebooks/analyze-results.ipynb`.

     ![individual_responses_image](./imgs/synthetic_individual_ouput.png)

   - `_summary`: percentile/mean/stddev stats plus error counts and completed-requests-per-minute.

     ![summary_output_image](./imgs/synthetic_summary_ouput.png)

   For multiple runs gathered into one table, see `notebooks/multiple-models-benchmark.ipynb` (pairs with a [Bundle](./benchmarking_bundles/README.md) run).

4. **Customize synthetic prompts** — found [here](./prompts/); add/edit/remove following the existing structure.

</details>

<details id="real-workload-dataset">
<summary><strong>Real Workload Dataset</summary></strong>

1. Set `--num-concurrent-requests` **less than** `--num-requests` (equal infers synthetic instead; or pass `--mode real_workload`). Relevant flags:
  - **`--model-names`**, **`--llm-api`**, **`--results-dir`** (_default_: `./data/results`) — same as Synthetic.
  - **`--qps`** (_default_: 0.5): requests/sec; <10 recommended.
  - **`--qps-distribution`** (_default_: `constant`): `constant` or `exponential`.
  - **`--num-warmup-requests`** (_default_: 0, fired together, not QPS-paced) and **`--timeout`** (_default_: 600) — same shared-budget semantics as Synthetic.
  - **`--num-input-tokens`** (_default_: 1000) / **`--num-output-tokens`** (_default_: 150) — recommended ≤2000.
  - **`--multimodal-image-size`** — same as Synthetic.
  - **`--num-requests`** (_default_: 16, may time out first).
  - **`--use-debugging-mode`** (_default_: False).

2. Run it — edit [`quickstart_real_workload.sh`](./benchmarking_tools/kit/quickstart_real_workload.sh) and `sh quickstart_real_workload.sh`, or call directly (no `--num-concurrent-requests` flag exists for this mode — QPS pacing is open-loop):
```shell
python benchmarking_tools/kit/src/evaluator.py \
  --mode real_workload \
  --model-names Meta-Llama-3.3-70B-Instruct \
  --results-dir ./data/results \
  --llm-api sncloud \
  --qps 1 \
  --qps-distribution constant \
  --num-requests 16 \
  --num-input-tokens 1000 \
  --num-output-tokens 1000 \
  --multimodal-image-size na
```

3. **Analyze results** — saved as `realworkload_<MODEL_IDX>_<MODEL_NAME><MULTIMODAL_SUFFIX>_{NUM_INPUT_TOKENS}_{NUM_OUTPUT_TOKENS}_{QPS}_{QPS_DISTRIBUTION}_{MODE}`, same `_individual_responses`/`_summary` pair as Synthetic:

   ![individual_responses_image](./imgs/real_workload_individual_ouput.png)
   ![summary_output_image](./imgs/real_workload_summary_ouput.png)

   Same multi-model table option via `notebooks/multiple-models-benchmark.ipynb`.

4. **Customize synthetic prompts** — found [here](./prompts/).

</details>

<details id="custom-dataset">
<summary><strong>Custom Dataset</summary></strong>

1. Passing `--input-file-path` infers **custom** mode (takes priority over synthetic/real_workload inference; or pass `--mode custom`). Relevant flags:
  - **`--model-names`** — space-separated for multiple models, run sequentially.
  - **`--llm-api`**, **`--results-dir`** (_default_: `./data/results`), **`--num-concurrent-requests`** (_default_: 16), **`--num-warmup-requests`** (_default_: 0), **`--timeout`** (_default_: 600) — same semantics as Synthetic.
  - **`--input-file-path`**: your dataset — see [example](./prompts/custom_prompt_example.jsonl).
  - **`--num-output-tokens`** (_default_: 150): same field as Synthetic/Real Workload — the API requires a concrete value, so this can't be left uncapped. An explicit `--sampling-params '{"max_tokens_to_generate": ...}'` overrides it if both are given.
  - **`--save-llm-responses`**, **`--use-debugging-mode`** — same as Synthetic.

2. Run it — edit [`quickstart_custom.sh`](./benchmarking_tools/kit/quickstart_custom.sh) and `sh quickstart_custom.sh`, or call directly:
```shell
python benchmarking_tools/kit/src/evaluator.py \
  --mode custom \
  --model-names Meta-Llama-3.3-70B-Instruct \
  --results-dir ./data/results \
  --llm-api sncloud \
  --num-concurrent-requests 16 \
  --input-file-path ./prompts/custom_prompt_example.jsonl \
  --num-output-tokens 150
```

3. **Analyze results** — saved as `custom_<MODEL_NAME>_{FILE_NAME}_{NUM_CONCURRENT_REQUESTS}_{MODE}`, same `_individual_responses`/`_summary` pair:

   ![individual_responses_image](./imgs/custom_individual_ouput.png)
   ![summary_output_image](./imgs/custom_summary_ouput.png)

</details>

# Third-party tools and data sources

All packages/tools used by the Kit's own evaluator are listed in `requirements.txt`.

Two other benchmarking tools run directly via their own native CLIs (not wrapped by this Kit):
- **vLLM** (`vllm bench serve`) — see [`vllm/README.md`](./benchmarking_tools/vllm/README.md).
- **aiperf** (NVIDIA's `aiperf`, including the AgentX MVP agentic-coding benchmark) — see [`aiperf/README.md`](./benchmarking_tools/aiperf/README.md).

# TroubleShooting

1. See the [FAQ](FAQ.md) for common questions and troubleshooting guidance.
2. If issues arise after updating: reinstall dependencies from `requirements.txt`; if that doesn't help, recreate your virtual environment and reinstall with `pip install --force-reinstall`; if problems persist, try a different package manager (pip, conda, uv).
3. [Known issue with macOS on Intel chips and PyTorch](https://dev-discuss.pytorch.org/t/pytorch-macos-x86-builds-deprecation-starting-january-2024/1690?utm_source=chatgpt.com) — recreate your virtual environment or try an alternative package manager.
